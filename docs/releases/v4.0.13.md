# SIGAB v4.0.13 — 2026-07-05

## Qué cambió
Primer punto cerrado de la petición directa de Gustavo sobre el módulo
Inventario (`docs/cerebro/CONTEXTO-COMPARTIDO.md`, punto 4/5): el **tipo de
adquisición** de un equipo ahora se puede editar desde la UI.

Antes, `EquipoDetail.jsx` mostraba `tipo_adquisicion` (Recurso Propio /
Consolidado / Garantía / Subrogado) como badge de solo lectura, pero
`EquipoForm.jsx` (el modal "Editar Equipo") no tenía ningún campo para ese
dato — no había forma de cambiarlo salvo tocando la base de datos
directamente.

- **`components/EquipoForm.jsx`**: nuevo `<select>` "Tipo de adquisición" en
  la sección "Mantenimiento y contrato", junto a proveedor de servicio y N°
  de contrato de servicio (mismo grupo temático que usa `EquipoDetail.jsx`
  para mostrarlo). Precarga el valor real del equipo al editar y usa
  "Recurso Propio" por defecto al crear uno nuevo.
- **`utils/constants.js`**: se centralizó `TIPO_ADQ_OPTIONS` (antes vivía
  solo dentro de `pages/Equipos.jsx`, usada únicamente por su filtro) para
  que el filtro de Inventario, el badge de `EquipoDetail.jsx` y el nuevo
  `<select>` de `EquipoForm.jsx` compartan una sola fuente de verdad del
  enum — evita que el día de mañana alguien agregue un valor al enum en un
  lugar y se le olvide en otro.

## Qué verificar
1. Inventario de Equipos → "Editar" en cualquier equipo: el campo "Tipo de
   adquisición" debe aparecer preseleccionado con el mismo valor que muestra
   el badge en el detalle del equipo.
2. Cambiar el valor, guardar, y confirmar que el badge de `EquipoDetail.jsx`
   refleja el cambio.
3. Crear un equipo nuevo: el campo debe mostrar "Recurso Propio" por
   defecto y guardarse sin errores.
4. Repetir en tema claro y oscuro — el `<select>` usa las clases de tema ya
   existentes en el resto del formulario, no debería haber sorpresas de
   contraste.

## Cómo revertir
`git revert` del commit de este cambio sobre `v4.0/piloto-clinica-1` +
redeploy del frontend. Es un cambio de formulario y constantes de UI, sin
migraciones de base de datos ni llamadas nuevas a la API — revert seguro.
