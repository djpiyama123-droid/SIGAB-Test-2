# v4.0.45 — Design system: badge de "área destino" en Historial de Equipo

**Fecha**: 2026-07-13
**Tipo**: patch
**Autor**: loop-thinkcentre

## Qué cambió

Continuando la clasificación del backlog de azul-como-acento (punto 4 de
`docs/DESIGN-SYSTEM-V4.md`), este ciclo revisó los dos candidatos señalados
al cierre de v4.0.44: `QRPanel.jsx` y `HistorialEquipoModal.jsx`.

- **`HistorialEquipoModal.jsx` (bug real, corregido)**: el badge de "área
  destino" en la pestaña Traslados del modal de Historial Técnico usaba
  `bg-blue-900/50 text-blue-300 border-blue-800`. `pages/Trazabilidad.jsx`
  muestra el mismo dato semántico (movimiento de un equipo de un área a
  otra) y ya usa `bg-emerald-900/50 text-emerald-300 border-emerald-800`
  desde v4.0.40 — sin razón categórica para que este componente hermano
  siguiera en azul. Migrado a emerald.
- **`QRPanel.jsx` (revisado, sin cambios)**: el botón "🏷️ Etiqueta A6"
  (`bg-blue-600`) descarga un PDF de etiqueta para impresión. Sigue la
  convención ya validada azul=documento, la misma que el botón "🖨️ PDF" de
  `OrdenDetalleModal.jsx` (confirmado sin bug en v4.0.44). No se tocó.

## Qué verificar

1. Inventario → abrir el detalle de un equipo con traslados registrados →
   botón "Historial" → pestaña "Traslados": el badge del área de destino de
   cada movimiento debe verse en verde, no azul. El badge de área de
   origen (neutral/gris) no cambia.
2. Desde la tarjeta o tabla de Inventario, abrir el panel de QR de un
   equipo: el botón "Etiqueta A6" debe seguir en azul (a propósito) y
   "Generar QR" en verde.
3. `npm run build` y `npx vitest run` en `sigab-frontend/` verdes (35
   tests). `grep -al anim-cell-pop dist/assets/Reservas-*.js` confirma que
   el heatmap de Reservas sigue intacto.

## Cómo revertir

`git revert` del commit de esta versión sobre `v4.0/piloto-clinica-1`.
Cambio de un solo archivo de frontend, solo clases Tailwind de color — sin
cambios de lógica de negocio ni de datos — revert seguro.
