# v4.0.62 — Órdenes: labels del modal "Nueva Orden de Servicio" rápida sin asociar a su input

**Fecha**: 2026-07-19
**Tipo**: patch
**Autor**: loop-thinkcentre

## Qué cambió

Continuación del barrido de accesibilidad de v4.0.59 (Reservas), v4.0.60
(Órdenes) y v4.0.61 (Equipos): `<label>` sin `htmlFor` asociado a su
control de formulario. Este ciclo toma el siguiente candidato por volumen
de la lista pendiente, dentro del mismo módulo Órdenes de la meta de
cierre v4.0: `components/OrdenServicioRapidaModal.jsx` — el modal de
"Nueva Orden de Servicio" que se abre desde el mapa/ficha técnica del
equipo, con 15 `<label>` sin asociar (el mayor de la lista pendiente).

A diferencia de `EquipoForm.jsx` (v4.0.61, un componente compartido), este
archivo declara cada campo por separado, mismo patrón manual que
Reservas/Órdenes:

- Se agregó `id`/`htmlFor` a los 11 campos con label+input hermano: tipo
  de mantenimiento, localización completa, falla reportada, hora de
  inicio, hora de término, tiempo estimado (hrs), tiempo real (hrs),
  técnico asignado, recibe de conformidad (nombre), matrícula (quien
  recibe) y descripción del trabajo/notas.
- El grupo de 3 radios "Prioridad" (Alta/Media/Baja) es distinto: un
  `<label>` de texto plano no describe un grupo de opciones, así que se
  reemplazó el `<div>`+`<label>` contenedor por `<fieldset>`+`<legend>`
  (con `border-0 p-0 m-0` para no alterar el layout visual) — primera vez
  que aparece este patrón en el código, es el fix WCAG correcto para
  grupos de radio buttons. Los 3 `<label>` que ya envuelven cada
  `<input type="radio">` individual tenían asociación implícita correcta
  y no se tocaron.

Cambio 100% aditivo (atributos `id`/`htmlFor` + 1 cambio de elemento
semánticamente equivalente para el grupo de radios), sin tocar clases,
layout, lógica de negocio ni el payload que se envía al backend.

## Qué verificar

- Dashboard o Mapa de Activos: abrir el botón "Abrir Orden de Servicio" de
  la ficha técnica de un equipo (o el flujo equivalente que monta
  `OrdenServicioRapidaModal`) y, con un lector de pantalla o el
  Accessibility Tree de DevTools, tabular por cada campo — debe anunciar
  el nombre del campo ("Tipo de mantenimiento", "Hora de inicio", "Técnico
  asignado", etc.), no solo el tipo de control.
- Confirmar que el grupo "Prioridad *" se ve idéntico (3 opciones
  Alta/Media/Baja en fila) — el cambio a `fieldset`/`legend` no debe
  alterar espaciado ni tamaño visual.
- Crear una orden de servicio de prueba con este modal y confirmar que se
  guarda correctamente (build+tests ya lo cubren, pero conviene una
  verificación manual del flujo real, formulario NOM-016).
- `npm run build` y `npx vitest run` en `sigab-frontend/` deben quedar
  verdes (62 tests, sin nuevos — cambio de puro markup/DOM).
