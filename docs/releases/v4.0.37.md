# v4.0.37 — Fix build: comentario CSS mal cerrado en la landing

**Fecha**: 2026-07-11 · **Tipo**: patch · **Autor**: loop-thinkcentre

## Qué cambió

`sigab-frontend/src/index.css` tenía un bloque de comentario sin su marca
de apertura `/*` desde el commit que introdujo la landing "Quirófano de
datos" (`a1e8ac45`, 2026-06-26). El texto:

```
   Landing cinematic — Dirección A "Quirófano de datos"
   CSS-first, 0 kb de lib. Todo respeta prefers-reduced-motion.
   ════════════════════════════════════════════════════════════════════ */
```

quedaba como CSS crudo inválido en vez de comentario, porque solo tenía el
cierre `*/`, no la apertura. `esbuild` (el minificador que usa Vite) lo
toleraba como *warning*, no como error, así que el build nunca falló y el
bug pasó inadvertido más de dos semanas — pero cada `npm run build` de
producción imprimía:

```
warnings when minifying css:
▲ [WARNING] Unexpected "\"Quirófano de datos\"" [css-syntax-error]
```

y el texto crudo del comentario terminaba filtrado al CSS final servido a
los usuarios (inofensivo para el layout — los navegadores también ignoran
declaraciones CSS inválidas — pero no debería estar ahí).

## Por qué

Un bug de build limpio importa aunque no rompa nada visualmente: esconde
warnings reales futuros entre el ruido, y deja bytes muertos en el bundle
servido. Se encontró al correr `npm run build` como parte de la exploración
de este ciclo (no reportado por Gustavo ni por ningún barrido anterior).

## Qué verificar

- `npm run build` en `sigab-frontend/` ya NO debe imprimir el warning
  `Unexpected literal` / `css-syntax-error`.
- La landing pública (`/`, sin login) debe verse exactamente igual que
  antes — el fix es de un comentario invisible en runtime, cero cambio de
  estilos aplicados.
- `npm run build` y `npx vitest run` en verde (35 tests).

## Rollback

`git revert` del commit de esta versión sobre `v4.0/piloto-clinica-1`.
Cambio de una sola línea de comentario CSS — revert seguro, no toca ninguna
regla de estilo real ni el calendario heatmap de Reservas.
