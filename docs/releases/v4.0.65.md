# v4.0.65 — Accesibilidad: labels de Almacén (Nueva Refacción / Ajustar Stock)

**Fecha**: 2026-07-20 · **Tipo**: patch · **Autor**: loop-thinkcentre

## Qué cambió

Continuación del séptimo barrido de accesibilidad (asociación `<label>` ↔
control de formulario vía `htmlFor`/`id`), iniciado en v4.0.59 y ya cerrado
para Reservas, Órdenes (2 modales), EquipoForm y EventoAdversoModal:

- `pages/Almacen.jsx` — modal `NuevaRefaccionModal`: se agregó `id`/`htmlFor`
  a los 7 campos (nombre, código interno, proveedor, stock inicial, stock
  mínimo, ubicación en almacén, compatible con).
- `pages/Almacen.jsx` — modal `AjustarStockModal`: se agregó `id`/`htmlFor`
  al campo "Cantidad". El campo "Movimiento" no es un `<input>` sino un
  grupo de 2 botones (`+ Entrada` / `- Salida`) que actúan como selector
  único — mismo caso que "Prioridad" (`OrdenServicioRapidaModal.jsx`,
  v4.0.62) y "Severidad" (`EventoAdversoModal.jsx`, v4.0.64). Se migró al
  mismo patrón `fieldset`/`legend`, y se agregó `aria-pressed` a cada botón
  para que un lector de pantalla anuncie cuál está seleccionado.

## Por qué

Sin `htmlFor`, un lector de pantalla anuncia el campo sin nombre al
enfocarlo con Tab — el usuario solo escucha "campo de texto" en vez de
"Stock mínimo". Es el mismo patrón de bug ya cerrado en 6 módulos previos
del mismo barrido; Almacén (9 labels/controles) era el mayor candidato
pendiente por volumen.

## Qué verificar

- Abrir "Nueva Refacción" desde Almacén y tabular por cada campo con un
  lector de pantalla (o el inspector de accesibilidad de DevTools) — cada
  campo debe anunciar su nombre (Nombre, Código interno, Proveedor, Stock
  inicial, Stock mínimo, Ubicación en almacén, Compatible con).
- Abrir "Ajustar Stock" sobre una refacción existente, tabular hasta los 2
  botones de Movimiento y confirmar que se ven exactamente igual que antes
  (mismo grid de 2 columnas, mismo resaltado del seleccionado) y que el
  lector de pantalla anuncia el estado "presionado"/seleccionado.
- Crear una refacción de prueba y ajustar su stock (entrada y salida) para
  confirmar que ambos formularios siguen guardando correctamente — el
  cambio es 100% de atributos de accesibilidad, no toca la lógica de
  guardado ni el payload.

## Cómo revertir

Rollback a v4.0.64 (`git revert` del commit de esta versión, o restaurar
`pages/Almacen.jsx` de esa versión). Sin cambios de base de datos ni de
backend.
