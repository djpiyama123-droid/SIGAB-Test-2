# SIGAB v4.0.15 — 2026-07-06

## Qué cambió
Tercer punto cerrado de la petición directa de Gustavo sobre el módulo
Inventario (`docs/cerebro/CONTEXTO-COMPARTIDO.md`, punto 2/5): más acciones
rápidas en el footer del modal de detalle de equipo, para no tener que abrir
el formulario completo (`EquipoForm.jsx`) para tareas frecuentes.

Antes, el footer de `components/EquipoDetail.jsx` solo tenía "Eliminar"
(izquierda) y "📱 QR" / "Cerrar" / "Editar" (derecha). Ya existían en el
código dos componentes reutilizables que solo se usaban desde otros lugares
(el mapa del Dashboard) — el pedido era enlazarlos también desde aquí, y
sumar un tercer atajo para el estado operativo.

- **`components/EquipoDetail.jsx`** — footer con 2 botones nuevos:
  - **"🎫 Nueva OS"** abre `OrdenServicioRapidaModal.jsx` pre-llenado con
    marca/modelo/ubicación del equipo, sin cerrar el detalle. Al crear la
    orden, la lista de "Tickets / Órdenes de Servicio" del mismo modal se
    refresca sola.
  - **"🕒 Historial"** abre `HistorialEquipoModal.jsx`, que suma la pestaña
    "Preventivos" — el resumen inline que ya tiene el detalle (Tickets +
    Traslados) no la mostraba.
  - El campo **"Estado"** de la grilla de información pasó de badge de solo
    lectura a un `<select>` que llama `api.updateEquipo(id, { estado })`
    directo — actualización optimista con rollback visual si falla la
    petición. Solo cubre los 3 estados que Gustavo pidió explícitamente:
    Operativo / En Mantenimiento / Fuera de Servicio. "En Traslado" y "Baja"
    quedan fuera a propósito porque dependen de otros flujos (traslados,
    baja definitiva) y no son un simple cambio de campo; si el equipo ya
    está en uno de esos dos, el select lo muestra como opción actual pero
    deshabilitada, para no ocultar el estado real ni dejar cambiarlo por
    accidente.
- **`pages/Equipos.jsx`** — nuevo prop `onQuickUpdate={cargar}` en
  `EquipoDetail`: recarga la lista de equipos en segundo plano tras un
  cambio rápido de estado, sin cerrar el modal (a diferencia de `onChange`,
  que sigue cerrando el modal para eliminar/editar, donde sí corresponde).

## Qué verificar
1. Inventario: abrir el detalle de cualquier equipo — el footer debe
   mostrar "Eliminar" a la izquierda y "Nueva OS" / "Historial" / "QR" /
   "Cerrar" / "Editar" a la derecha (puede envolver a 2 líneas en pantallas
   angostas, es intencional).
2. "Nueva OS": crear una orden desde ahí y confirmar que aparece en la
   lista de tickets del mismo modal sin tener que cerrarlo y reabrirlo.
3. "Historial": debe abrir con las 3 pestañas (Órdenes, Traslados,
   Preventivos) para ese equipo.
4. Cambiar el `<select>` de Estado — el badge de color debe reflejar el
   cambio de inmediato y el toast debe confirmarlo. Cerrar y reabrir el
   mismo equipo para confirmar que quedó guardado.
5. Si hay algún equipo en "En Traslado" o "Baja" en el inventario real, el
   select debe mostrarlo como opción actual pero deshabilitada.
6. Repetir el flujo completo en móvil (iPhone/iPad) — botones del footer y
   el select de estado deben responder bien al tacto.

## Cómo revertir
`git revert` del commit de este cambio sobre `v4.0/piloto-clinica-1` +
redeploy del frontend. Cambio de UI más una llamada PUT que ya existía en
el backend (`api.updateEquipo`, la misma que usa `EquipoForm.jsx`) — revert
seguro, sin migraciones de base de datos.
