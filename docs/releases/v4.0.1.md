# SIGAB v4.0.1 — 2026-07-03

## Qué cambió
Optimización de rendimiento del Dashboard (la pantalla que ve todo usuario al
iniciar sesión) y arreglo de un gate de tests que no estaba corriendo.

- El Dashboard usaba `@tremor/react` solo como envoltorio visual (`Card`,
  `Title`, `Text`, `Flex`, `BadgeDelta`) para las tarjetas KPI y las secciones
  del mapa/gráfica. Esa librería venía empaquetada junto con `recharts` y
  `d3` en un mismo "chunk" de 1.3 MB (361 KB comprimido) que el navegador
  tenía que descargar y ejecutar ANTES de poder pintar las tarjetas KPI —
  aunque esas tarjetas no dibujan ninguna gráfica.
- Se quitó `@tremor/react` por completo (ya no se usa en ningún archivo) y se
  reemplazó por el mismo diseño con Tailwind plano. El chunk de gráficas bajó
  de 1.3 MB a 530 KB (159 KB comprimido).
- La gráfica de barras "Cumplimiento de Mantenimiento" ahora se carga de
  forma diferida (`React.lazy` + `Suspense`): los KPIs y el mapa del Dashboard
  ya no esperan a que termine de bajar el chunk de gráficas.
- Se corrigió `sigab-frontend/src/utils/fechas.test.js`: usaba la API nativa
  de Node (`node:test`), invisible para el comando `npx vitest run` que exige
  el ciclo de mejora continua. Los 8 casos de esa suite (parseo de fechas de
  Reservas, agrupación por día, etc.) llevaban tiempo sin ejecutarse en el
  gate automático. Ahora corren y pasan.

## Por qué
Backlog de rendimiento documentado en `docs/CONSOLIDACION-V4.md` §7 ("recortar
bundle de gráficas, 1.3 MB / 361 kB gzip — candidato"). El Dashboard es la
primera pantalla que ve cualquier técnico/operador tras iniciar sesión, así
que su tiempo de carga inicial es el más visible de toda la app.

## Qué verificar
1. Entrar a SIGAB y mirar el Dashboard: las 4 tarjetas KPI arriba deben verse
   igual que antes (borde superior de color, icono a la derecha, flechita de
   tendencia abajo con "Vs. mes anterior").
2. Bajar hasta "Cumplimiento de Mantenimiento": debe aparecer la gráfica de
   barras (Programadas vs. Completadas). Puede haber un parpadeo gris muy
   breve antes de que cargue — es esperado y no es un error.
3. El Mapa de Activos por Zona debe seguir funcionando igual (clicks en
   zonas, indicador Wifi verde arriba a la derecha).
4. Probar en escritorio y en móvil (breakpoints `isControlRoom`).

## Cómo revertir
Si algo se ve mal en el Dashboard:
```
git revert <commit-de-esta-version>
```
sobre `v4.0/piloto-clinica-1`, luego redeploy del frontend (build + rsync del
`dist` anterior si ya se había desplegado esta versión).
