# v4.0.63 — Órdenes: labels del modal reutilizable "Nueva Orden de Servicio" sin asociar a su input

**Fecha**: 2026-07-19
**Tipo**: patch
**Autor**: loop-thinkcentre

## Qué cambió

Continuación del barrido de accesibilidad de v4.0.59 (Reservas), v4.0.60
(Órdenes), v4.0.61 (Equipos) y v4.0.62 (`OrdenServicioRapidaModal.jsx`):
`<label>` sin `htmlFor` asociado a su control de formulario. Este ciclo
toma el siguiente candidato por volumen dentro del mismo módulo Órdenes:
`components/NuevaOrdenModal.jsx` — el modal reutilizable de "Nueva Orden
de Servicio" que se monta desde `pages/Ordenes.jsx`, la ficha técnica del
mapa de activos y `EquipoDetail.jsx`, con 11 `<label>` sin asociar.

- Se agregó `id`/`htmlFor` a los 11 campos: equipo (nombre), N° de serie,
  técnico, área, piso, tipo de mantenimiento, prioridad, localización
  completa, falla reportada, hora de inicio, hora de término, tiempo
  estimado (hrs), tiempo real (hrs), recibe de conformidad (nombre) y
  matrícula.
- 5 de esos campos se generan dinámicamente vía `.map()` sobre un arreglo
  de `[clave, etiqueta, tipo]` — el `id` se derivó de la clave del campo
  (`nueva-orden-${k}`) para que cada label quede único sin duplicar código.
- Los 2 `<select>` (Tipo, Prioridad) recibieron el mismo tratamiento. A
  diferencia de `OrdenServicioRapidaModal.jsx` (v4.0.62), este archivo usa
  un `<select>` simple para prioridad, no un grupo de radios — no aplicó
  el patrón `fieldset`/`legend` introducido en ese ciclo.

Cambio 100% aditivo (solo atributos `id`/`htmlFor`), sin tocar clases,
layout, lógica de negocio ni el payload que se envía al backend.

## Qué verificar

- Desde `pages/Ordenes.jsx`, la ficha técnica de un equipo en el mapa, o el
  footer de `EquipoDetail.jsx` ("🎫 Nueva OS"): abrir el modal "Nueva Orden
  de Servicio" y, con un lector de pantalla o el Accessibility Tree de
  DevTools, tabular por cada campo — debe anunciar el nombre del campo
  ("Equipo (nombre)", "Hora de inicio", "Recibe de conformidad (Nombre)",
  etc.), no solo el tipo de control.
- Confirmar que el layout/espaciado del formulario se ve idéntico en los
  3 puntos de entrada (Ordenes, mapa, EquipoDetail) — el cambio es solo de
  atributos, no debe alterar nada visual.
- Crear una orden de servicio de prueba con este modal y confirmar que se
  guarda correctamente (build+tests ya lo cubren, pero conviene una
  verificación manual del flujo real).
- `npm run build` y `npx vitest run` en `sigab-frontend/` deben quedar
  verdes (62 tests, sin nuevos — cambio de puro markup/DOM).
